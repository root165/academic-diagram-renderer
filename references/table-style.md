# Academic report tables

Determine whether the table presents data, compares options, traces requirements, defines fields, assesses risks, or supports a decision. Preserve the supplied institutional/journal/client template over every default below.

Without a supplied template, use a restrained three-line academic table when suitable: top rule, rule below the header, bottom rule; normally no vertical gridlines, gradients, shadows, or decorative fill. A three-line table is a convention, not a universal law: dense traceability or risk tables may need light internal rules for legibility.

- Put the numbered title above the table; put source and explanatory notes below it.
- Put units in the heading or title, not repeatedly in data cells.
- Right-align numbers and make decimal precision consistent; left-align text; use meaningful row labels.
- Default to monochrome: black text, white paper, black/grey rules, and at most a very light grey header fill (`#F2F2F2`). Do not use a blue header merely because an Office template defaults to one.
- Do not use colour as the only carrier of meaning. If a cell must be emphasised, use bold, a symbol, or a note as well; check the table in grayscale/print.
- If the school/journal template mandates colour, it overrides this default. Record the template and keep the table readable in grayscale.
- Do not manufacture data, units, methods, sources, or statistical precision.

When creating a native Word/WPS table, use these rules for style, but keep diagrams as validated external/vector assets. A `table` IR declares the same `visual_style` as a diagram; use `palette: "monochrome"` unless the template is the explicit source of a colour scheme.
